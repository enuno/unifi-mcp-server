The UniFi MCP Server exposes UniFi Network, UniFi Protect, and the UniFi cloud
APIs (Site Manager, Mobility, InnerSpace, Carrier Fabric) as MCP tools, so an
AI agent can read and change UniFi infrastructure through one standard
interface. It runs against a single controller or, in fleet mode, many.

<Note>
  Current release: **0.6.1**. 343 tools in local mode, from 60 modules.
</Note>

## Quick start

<CodeGroup>

```bash npm
# Install and run
uvx unifi-mcp-server --help

# Configure the credentials once
export UNIFI_API_KEY=your-api-key
export UNIFI_API_TYPE=local
export UNIFI_LOCAL_HOST=192.168.2.1

# Call a tool directly, without loading every tool into context
unifi-cli list-clients --site default
```

```json MCP client
{
  "mcpServers": {
    "unifi": {
      "command": "uvx",
      "args": ["unifi-mcp-server"],
      "env": {
        "UNIFI_API_KEY": "your-api-key",
        "UNIFI_API_TYPE": "local",
        "UNIFI_LOCAL_HOST": "192.168.2.1"
      }
    }
  }
}
```

</CodeGroup>

### Scoped profiles

Start the server with only the tools you need, to keep the tool list small:

```bash
UNIFI_PROFILE=network unifi-mcp-server    # clients, VLANs, WiFi, DHCP, DNS
UNIFI_PROFILE=devices unifi-mcp-server    # device management and control
UNIFI_PROFILE=security unifi-mcp-server   # firewall, VPN, ACLs, content filtering
UNIFI_PROFILE=system unifi-mcp-server     # backups, QoS, traffic flows, sites
UNIFI_PROFILE=protect unifi-mcp-server    # cameras, NVRs, sensors, alarms
```

## API modes

Set `UNIFI_API_TYPE` to choose how the server reaches UniFi.

| Mode | What it reaches | Use it for |
| --- | --- | --- |
| `local` (recommended) | Your UniFi console or gateway on the LAN (`UNIFI_LOCAL_HOST`) | Everything: device and client control, configuration, firewall, Protect |
| `cloud-v1` | UniFi's cloud API | Sites and aggregate statistics; no per-device control or configuration |
| `cloud-ea` | UniFi's Early Access cloud API | Sites and aggregate statistics; no per-device control or configuration |

Zone-based firewall, traffic flows, ACLs, device and client management, and
Protect all require `local` mode.

## Safety controls

Every mutating tool requires `confirm=True` and supports `dry_run=True`. The
server also offers read-only and dry-run modes, role-based access over risk
tiers, and a hash-chained audit log. See [Tool profiles and safety
controls](/SPEC) and the [security policy](/SECURITY).
